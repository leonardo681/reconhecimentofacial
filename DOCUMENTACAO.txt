2. VISÃO GERAL
--------------------------------------------------------------------------------

Este projeto é uma aplicação web de reconhecimento facial que roda inteiramente
no navegador do usuário. Não há servidor backend dedicado ao processamento de
imagens: a detecção e a correspondência de rostos são feitas localmente com
modelos de inteligência artificial carregados via face-api.js.

A interface foi pensada para uso institucional, com cabeçalho e rodapé
referenciando a PMSC, e permite:

  - Consultar se uma pessoa capturada pela câmera ou enviada por arquivo já
    está cadastrada na base de rostos conhecidos;
  - Identificar múltiplos rostos em uma mesma imagem;
  - Cadastrar rapidamente pessoas desconhecidas durante uma consulta.

Os dados de pessoas cadastradas ficam em memória durante a sessão. Novos
cadastros feitos pelo usuário são adicionados à base em tempo real, mas não
são persistidos em banco de dados ou armazenamento local após recarregar a
página (a interface avisa e pede confirmação antes de sair da página).

4. ARQUITETURA DA APLICAÇÃO
--------------------------------------------------------------------------------

A aplicação segue uma arquitetura SPA (Single Page Application) com a lógica
principal dividida em camadas:

  [Interface]  Index.tsx, CameraCapture, FaceOverlay, QuickRegister
       |
  [Hook]       useFaceRecognition.ts — carrega modelos, monta base, faz matching
       |
  [Biblioteca] src/lib — geometria das caixas, comparação, imagens, cache,
       |                 mensagens da câmera (funções puras, com testes)
       |
  [IA]         face-api.js — detecção e descritores faciais
       |
  [Dados]      persons.ts (pessoas e fotos) + descritoresReferencia.json

Fluxo da tela principal (Index.tsx):

  Câmera ao vivo --Capturar/Enviar imagem--> Imagem congelada + caixas + cartões
       ^                                            |
       +------------- Nova Consulta ----------------+
                                                    |
                                    Cadastrar rosto #N (tela de cadastro)

  - A imagem analisada fica congelada no quadro, com as caixas alinhadas.
  - "Nenhum rosto detectado" aparece na própria tela (sem trocar de tela).
  - A tela de cadastro entra no histórico do navegador: o botão/gesto
    "voltar" do celular volta para a câmera em vez de sair do app.

5. FUNCIONALIDADES DETALHADAS
--------------------------------------------------------------------------------

5.1 Captura pela câmera
  - Acesso via WebRTC (navigator.mediaDevices.getUserMedia)
  - Suporte a câmera frontal (user) e traseira (environment)
  - Detecção automática quando o dispositivo possui apenas uma câmera
  - Resolução ideal: 640x480
  - "Capturar" só fica disponível quando o vídeo já tem imagem
  - A câmera é desligada ao sair da tela de captura e quando a aba vai para
    segundo plano; pedidos de câmera antigos são descartados (sem vazamento)
  - Mensagens específicas: permissão negada, câmera em uso, câmera
    inexistente, conexão sem HTTPS
  - Botão para reiniciar o stream da câmera

5.2 Envio de imagem
  - Formatos aceitos: JPG, JPEG, PNG, WEBP
  - Validação por MIME type e extensão do arquivo
  - Arquivo inválido mostra uma mensagem de erro (a tela não trava)
  - Fotos grandes são reduzidas para no máximo 1280 px no maior lado

5.3 Detecção e identificação de rostos
  - Detecção de múltiplos rostos por imagem (detectAllFaces)
  - Rostos numerados da esquerda para a direita (#1, #2…), na imagem e nos
    cartões
  - Caixas desenhadas sobre a imagem congelada, alinhadas em qualquer
    proporção (retrato, paisagem, 16:9) e com rótulos legíveis:
      * Verde  = pessoa identificada
      * Vermelho = pessoa desconhecida
  - Uma mesma pessoa não é atribuída a dois rostos da mesma imagem
  - Cada correspondência mostra a faixa (alta, média ou baixa) e o percentual
  - Aviso fixo: o resultado é uma sugestão automática

5.4 Cadastro rápido
  - Disponível para rostos não identificados (botão "Cadastrar" no cartão)
  - Cadastra o rosto escolhido (descritor e recorte daquele rosto)
  - Campos: nome completo (obrigatório), marcas corporais (tipo, local,
    observação), observações gerais e fotos adicionais
  - Fotos adicionais sem rosto ou que parecem ser de outra pessoa são
    recusadas, com aviso
  - O cadastro entra na base sem reprocessar as outras fotos e o rosto passa
    a aparecer como identificado na consulta atual
  - Envio protegido contra clique duplo, com mensagem de sucesso ou de erro

5.5 Base inicial de pessoas
  - 12 pessoas pré-cadastradas com fotos em src/assets/persons/
  - Nomes: Henrique, Isabella, Issaga, Leandro, Leonardo, Letícia, Luciano,
    Marcelo, Maria Eduarda, Rithiély, Carlos Augusto Bohn, Rodrigo Delduque
  - Os descritores dessas fotos já vêm calculados em
    src/data/descritoresReferencia.json (identificados pelo hash da foto)

6. ALGORITMO DE RECONHECIMENTO FACIAL
--------------------------------------------------------------------------------

O face-api.js utiliza redes neurais pré-treinadas para:

  1. Detectar rostos na imagem (SSD MobileNet v1)
  2. Localizar 68 pontos de referência facial (landmarks)
  3. Gerar um vetor descritor de 128 dimensões (face descriptor)

A correspondência entre rostos é feita pela distância euclidiana entre os
descritores. Quanto menor a distância, mais semelhantes são os rostos.

Parâmetros configurados (src/lib/faceDescriptorSimilarity.ts):

  FACE_MATCH_DISTANCE_THRESHOLD = 0.6
    - Limiar para considerar um match válido
    - Distâncias abaixo de 0.6 indicam correspondência no banco
    - Faixa típica para a mesma pessoa: ~0,15 a 0,5

  Faixas exibidas:
    - Alta:  distância < 0,40
    - Média: 0,40 a 0,50
    - Baixa: 0,50 a 0,60 ("confira visualmente")

  Percentual de compatibilidade exibido na interface:
    - Conversão não linear da distância euclidiana para 0–100%
    - Referência de exibição: 0.88
    - Curvatura (gamma): 0.28
    - Fórmula: 100 * ((ref - d) / ref) ^ gamma
    - Atenção: com essa escala, todo match aparece entre ~73% e 100%;
      por isso a faixa qualitativa é mostrada junto

Atribuição dos rostos (src/lib/faceMatching.ts):
  - Para cada par (rosto, pessoa) abaixo do limiar, escolhe do mais próximo
    para o mais distante, sem repetir pessoa; o que sobra é desconhecido.

Carregamento dos modelos (useFaceRecognition.ts):
  1. A biblioteca face-api.js é baixada sob demanda (import dinâmico), então a
     interface e a câmera aparecem antes
  2. Cada modelo tenta public/models/ (local, no deploy); só o modelo que
     falhar é baixado da CDN jsDelivr com versão fixa (0.22.2), com tempo
     limite de 60 s e indicador de progresso
  3. Base de referência: para cada foto, usa o descritor pré-calculado
     (JSON), depois o cache do navegador (localStorage) e, só se não houver,
     calcula na hora. Tudo é indexado pelo hash SHA-256 da foto.

8. COMO INSTALAR E EXECUTAR
--------------------------------------------------------------------------------

Requisitos:
  - Node.js 20.19 ou superior (recomendado 22 ou 24 LTS)
  - Navegador com suporte a WebRTC (getUserMedia) para uso da câmera
  - A câmera só funciona em HTTPS ou em localhost

Instalação:

  npm install

Desenvolvimento:

  npm run dev

  A aplicação abre em http://localhost:8080

Teste no celular (rede local com HTTPS):

  npm run dev:celular

Build de produção:

  npm run build

  Gera a pasta dist/ com index.html, 404.html e .nojekyll (GitHub Pages).
  Funciona igual no Windows, no Linux e no macOS.

Preview do build:

  npm run preview      (http://localhost:4173/reconhecimentofacial/)

Outros comandos:

  npm run lint         Verificação ESLint
  npm run typecheck    Checagem de tipos
  npm test             Testes unitários (Vitest)
  npm run test:e2e     Teste de ponta a ponta (Playwright + Chrome)
  npm run verificar    Lint + tipos + testes + build
  npm run descritores  Recalcula os descritores da base inicial

Observações para Windows:
  - No PowerShell, se o npm for bloqueado pela política de execução, use
    npm.cmd (ex.: npm.cmd run dev) ou o Prompt de Comando.
  - Evite pastas sincronizadas pelo OneDrive para o projeto.
  - Não abra o index.html direto nem pelo Live Server (página em branco).

9. DEPLOY (GITHUB PAGES)
--------------------------------------------------------------------------------

O projeto está configurado para publicação em:

  https://<usuario>.github.io/reconhecimentofacial/

Configuração:
  - base URL em produção: /reconhecimentofacial/ (vite.config.ts)
  - Workflow: .github/workflows/deploy-pages.yml
  - A cada push na branch main (exceto alterações só em docs/), o CI:
      1. Instala dependências (npm ci, Node da versão do .nvmrc)
      2. Roda lint, checagem de tipos e testes (se falhar, não publica)
      3. Executa npm run build
      4. Copia dist/ para a pasta docs/ na branch main

No GitHub: Settings → Pages → Deploy from branch → main → /docs
Depois de cada deploy o bot faz um commit na main: faça git pull antes do
próximo push.

11. MODELO DE DADOS
--------------------------------------------------------------------------------

Interface Person (src/data/persons.ts):

  id: string              Identificador único
  name: string            Nome completo
  imageSrc: string        URL ou data URL da foto (no cadastro: recorte do rosto)
  notes?: string          Observações opcionais
  bodyMarks?: BodyMark[]  Marcas corporais (tipo, local, observação)
  registeredAt: string    Data de cadastro (AAAA-MM-DD, horário local)
  additionalPhotos?: string[]  Fotos adicionais aceitas no cadastro

Interface BodyMark:

  id: string
  type: "tatuagem" | "cicatriz"
  location?: "braco" | "perna" | "costas" | "rosto" | "maos"
  observation?: string

Durante o runtime, cada foto de referência gera um descritor facial
(Float32Array de 128 elementos) armazenado em memória no hook
useFaceRecognition.


--------------------------------------------------------------------------------
12. LIMITAÇÕES E CONSIDERAÇÕES
--------------------------------------------------------------------------------

  - Dados não persistem: cadastros feitos na sessão são perdidos ao recarregar
  - Processamento 100% client-side: performance depende do dispositivo; em
    computadores lentos (ex.: processador limitado a baixa frequência) cada
    análise pode levar minutos
  - Qualidade da identificação varia com iluminação, ângulo e resolução
  - O percentual exibido é uma escala visual, não probabilidade estatística
  - Requer permissão de câmera no navegador (e HTTPS fora do localhost)
  - Modelos de IA têm tamanho considerável (~12 MB) na primeira carga
  - As fotos da base ficam públicas no site publicado: use com consentimento
  - Projeto acadêmico — não substitui sistemas biométricos certificados
